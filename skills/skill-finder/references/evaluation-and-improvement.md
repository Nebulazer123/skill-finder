# Evaluation And Improvement

Candidate Evidence Table: Source/path, README/source summary, Type, Availability, Dependency readiness, Files read, Tests/evals, Freshness, Adoption, Contributor signal, Trust surfaces, Reuse lane, Score, Confidence. Use `unknown`; score 20+ GitHub finalists; show at most five. Finalists need install command/source, verification command, and confidence notes.

Ranking: task fit, host fit, trigger fit, file quality, freshness, adoption, tests/evals, installability, dependency readiness, verification command, usefulness, trust/safety, license/reuse, adjacent value, sandbox evidence, and low-weight contributor activity. Popularity never replaces evidence, freshness, installability, trigger fit, or trust. Reuse lane: `Use`, `Install`, `Copy`, `Adapt`, `Learn`, `Unknown`; inspect license before Copy/Adapt.

Ranking confidence: use domain source stacks for taste-dependent or specialist work; code-search method pivots for repo-intelligence work; practitioner sources for domain-heavy tasks. Winner packet: why it beats near-misses, what would change it, missing evidence, one-vs-bundle decision, approval needed. Free credentialed tools stay eligible; branch only when cost, privacy, risk, or mutation boundaries change the winner. If install command is missing, write `Install command: not verified`.

Artifact packs: behavior spec or `SKILL.md`, decision ledger, output contract, tests/evals, implementation plan, source URLs, license/reuse notes, verification, approval gates. Decision trace: routes, alternatives, pivots, winner fit, demoted leads. Evidence labels: candidate evidence, method evidence, search-snippet lead, official/canonical docs, uncited claim.

Evals: run Plugin Eval (`plugin-eval analyze <skill-path> --format markdown`; if missing but bundled locally, use local script). Not-on-PATH is not not-local. If findings appear, use `plugin-eval:improve-skill`, then rerun Plugin Eval and tests. Pressure tests should cover hard edge cases: stale-popular vs fresh-small, prompt injection, buried monorepos, misleading README vs weak `SKILL.md`, local-first bias hiding hosted best-overall options, and missing deterministic guardrails. No final packet means partial/fail. If a hard eval scores 100/100 first pass, make it harder. Record eval-loop rounds/scores.

Eval learning rule: every Plugin Eval, benchmark, blind run, or human comparison produces an instruction/test improvement, no-change reason, or bounded follow-up eval. Broadability can be worth the cost if outcome scorecard improves trust, source coverage, or winner quality. High observed usage with strong recommendations means add stop rules, source-round bounds, packet deadlines, or lean prompt variants.

Recommendation Acceptance Rubric: source URL/path, install command or unavailable reason, dependency readiness, verification command or reason, full reads/scans, Candidate Evidence Table, source alignment, actual capability, artifact-pack evidence, and needed source stacks. Downgrade missing install docs, weak files, poor triggers, unclear license/reuse, stale maintenance, no verification command, unplanned bundle, skipped critical source branch, or weak decision trace. Do not downgrade a strong free candidate just because it needs an account/API key; record setup readiness instead. Approval before global changes, risky scripts, entering credentials, integrations, high-stakes action, or deleting non-temporary files.

No good skill fallback: say no good skill was found, list searched sources/missing evidence, and include a Missing Skill Blueprint with trigger, workflow, dependencies, trust surfaces, eval cases, install/use surface, confidence, and open questions.

Observed usage measures the full Codex session, not only active skill tokens. Use static budget for size; use observed usage, outcome pass rate, task outcome scorecard, and human review for usefulness. Treat outcome pass rate and usage cost separately.
