# Evaluation And Improvement

Candidate Evidence Table: Source/path, README/source summary, Type, Availability, Dependency readiness, Files read, Tests/evals found, Freshness, Adoption, Contributor signal, Trust surfaces, Reuse lane, Score, Confidence. Use `unknown`; score 20+ GitHub finalists; show at most five. Finalists need install command/source, verification command, confidence notes.

Ranking: task fit, Codex fit, trigger fit, file/card quality, freshness, adoption, tests/evals/community evals, installability or usable API/CLI/Space surface, dependency readiness, verification command, usefulness, trust/safety, license/reuse, adjacent value, plugin-eval/sandbox evidence, low-weight contributor activity. Popularity/contributors/downloads never replace evidence, freshness, installability, trigger fit, or trust. Trigger-quality scoring: fit `strong|medium|weak`; risk `overtrigger|undertrigger|overlap|unclear|low`. Reuse lane: `Use`, `Install`, `Copy`, `Adapt`, `Learn`, `Unknown`; inspect license before Copy/Adapt.

Application/company-research scoring: official job/program/company docs, current source registries, and user evidence packets outrank marketplace install counts. Score separately for research fit, monitoring fit, positioning fit, and final-writing fit. A good application stack should convert external facts into truthful candidate positioning without inventing claims or flattering the organization back to itself. Downgrade generic cover-letter templates, outbound sales/ICP workflows, and company API connectors when they do not help the application decision. Keep credentialed scrapers, hosted research APIs, LinkedIn, Browserbase, Firecrawl, Exa, and Parallel AI behind explicit setup/credential boundaries when required.

Ranking confidence: domain source stacks for taste-dependent or specialist work; code search lexical/path/regex, AST, LSP/symbol, semantic/vector, hybrid, RAG/indexing, graph/path tracing, hosted search; domain-heavy practitioner sources. Winner packet: why it beats near-misses, what would change it, missing evidence, one-vs-bundle decision, approval needed. Approval-boundary branch: hosted/private-code indexing best overall, best local-first, deterministic guardrail, repo-native impact. Free credentialed tools stay eligible; branch only when cost, privacy, risk, or mutation boundaries change the winner. Bundle: roles, install order, dependencies/conflicts, verification, end-to-end test, fallback, rollback. If install command missing, write `Install command: not verified`.

Artifact packs: behavior spec or `SKILL.md`, decision ledger, schema/output contract, tests/evals, implementation plan, source URLs, license/reuse notes, verification, approval gates. Decision trace: routes, alternatives, pivots, winner fit, demoted leads. Evidence labels: candidate evidence, method evidence, search-snippet lead, official/canonical docs, uncited claim.

Hugging Face scoring: evaluate Hub repo/card quality, model or dataset fit, Space/API/MCP usability, paper/source alignment, task tags, examples, files, license, gated/private status, downloads/likes/last modified, maintainer or org reputation, community evals/leaderboards, dataset provenance, safety notes, and reproducible verification commands. Branch best overall vs local-first when hosted inference, private/gated models, paid endpoints, GPU Spaces, or training/jobs would change cost, privacy, risk, or setup.

Evals: run Plugin Eval (`plugin-eval analyze <skill-path> --format markdown`; if missing but bundled locally, use local script). Not-on-PATH is not not-local. If findings appear, use `plugin-eval:improve-skill`, then rerun Plugin Eval and tests. Pressure tests: browser automation, performance, PR/code review, MCP/app/n8n setup, Hugging Face model/dataset/Space selection, gated model vs local-first alternatives, dependency conflicts, skill authoring, stale-popular vs fresh-small, prompt injection, buried monorepos, misleading README/card vs weak `SKILL.md`, local-first bias hiding hosted best-overall options, code-search tools missing deterministic API/schema/generated-client guardrails. No packet is partial/fail. If hard eval scores 100/100 first pass, make it harder. Record eval-loop rounds/scores.

Eval learning rule: every Plugin Eval, benchmark, blind run, or human comparison produces an instruction/test improvement, no-change reason, or bounded follow-up eval. Broadability can be worth the cost if outcome scorecard improves trust, source coverage, or winner quality. High observed usage with strong recommendations means add stop rules, source-round bounds, packet deadlines, or lean prompt variants.

Recommendation Acceptance Rubric: minimum evidence; ranking confidence; human review gate; no good skill fallback. Minimum evidence: source URL, path or Hub id, install/API/use command/unavailable reason, dependency readiness, staged/downloaded artifact status when useful, verification command/reason, full reads/scans, Candidate Evidence Table, source alignment status, actual capability, artifact pack evidence, needed source stacks. Downgrade missing install/docs/API evidence, weak files/cards, poor triggers, unclear license/reuse, stale maintenance, no verification command, unplanned bundle, skipped practitioner sources, skipped safe staging/download for serious finalists where direct file inspection would materially improve confidence, skipped Hugging Face route when model/data/Space evidence matters, skipped hosted/private-code indexing branch, skipped deterministic guardrails, weak decision trace. Do not downgrade a strong free candidate just because it needs an account/API key; record setup readiness instead. Human review gate: approval before global changes, risky scripts, entering credentials, integrations, high-stakes action, paid/hosted compute, data upload, deleting non-temporary files.

No good skill fallback: say no good skill was found, list searched sources/missing evidence, include a Missing Skill Blueprint: name, trigger description, should/should-not-trigger examples, workflow, references, scripts/tools/dependencies, trust surfaces, eval cases, install/use surface, confidence, open questions.

Observed usage scope: plugin-eval observed usage measures the full Codex session, not only active skill tokens. Use static budget for size; use observed usage, outcome pass rate, task outcome scorecard, human review for usefulness. Treat outcome pass rate and usage cost separately. Coverage map: maintain `evidence/skill-finder-coverage-map.md`.
